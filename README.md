# ゆうしゃとまおう(非同期攻防型ダンジョンゲーム プロトタイプ)

魔王がダンジョンを掘って生態系を育て、勇者パーティが5層のダンジョンを順に攻略するゲームのプロトタイプです。
今回はオフライン版で、全層とも NPC 製のダンジョンを使います。オンライン化(AWS 上のサーバーでの勝敗再計算)を見据えて、
ゲームロジックは Unity に依存しない純粋な C# に分け、すべて決定論的に動くように作っています。

- Unity 6000.5.8f1(2D / URP テンプレート)
- ビルドターゲット:WebGL(Android は今後)
- 見た目はレトロなドット絵風(IMGUI)。絵はすべてコード内の文字列から生成するオリジナル素材
  (`Assets/Scripts/Client/Art/Sprites.cs` の文字列を書き換えると絵が変わる)

---

## フォルダ構成

```
Assets/
  Scripts/
    Core/                 … ゲームロジック(DungeonGame.Core.asmdef:UnityEngine 参照なし)
      Determinism/        … 決定論的乱数(xorshift128)、整数演算、状態ハッシュ
      Simulation/         … 固定ティック(1ティック=0.1秒)、ITickSimulation
      Dungeon/            … グリッド、掘削、経路探索、保存時の検証、魔王側の編集窓口(DungeonBuilder)
      Ecology/            … モンスター定義、掘削時の誕生、生態系シミュレーション(食物連鎖)
      Heroes/             … 勇者の職業定義
      Raid/               … 勇者AI・戦闘・霧・介入スキル(回復/たいまつ)の攻略シミュレーション
      Skills/             … スキル定義と能力値計算
      Run/                … ラン(全層の攻略)、★評価、入力ログ、リプレイ/検証、NPCダンジョン(抽選・生成)、自動プレイヤー
      Serialization/      … JSON 変換(Newtonsoft.Json)、ダンジョンのスナップショット
      Data/               … 定義データ一式(GameData)
    Client/               … Unity 側(DungeonGame.Client.asmdef):画面、マップ描画、演出、固定ティックの駆動、保存
      Art/                … ドット絵(モンスター・勇者・アイコン)と地面タイルの生成
      Audio/              … BGM・効果音の合成(ファミコン風のシンセサイザー、曲は文字列の楽譜)
    Editor/               … エディタ専用(DungeonGame.Editor.asmdef):WebGL ビルドスクリプト
  Tests/EditMode/         … EditMode 単体テスト(DungeonGame.Core.Tests.asmdef)
  Resources/
    GameData/
      layer_rules.json    … 層ごとのルール(掘削予算・解放モンスター・ゴール・育成時間 など)
      monsters.json       … モンスター11体(誕生条件・特殊な誕生・進化・食性・戦闘能力)
      heroes.json         … 勇者の職業4種、介入スキルの回数、テスト防衛のパーティ
      skills.json         … スキル13種、スキルポイントの設定
      NpcDungeons/        … NPC 製ダンジョン(各層3個、スナップショット JSON)
    Fonts/                … DotGothic16(見出し・ボタン)と BIZ UDゴシック(説明文)。どちらも SIL Open Font License 1.1、ライセンス文書同梱
  Scenes/SampleScene.unity … 起動シーン(中身は空。GameApp が自動生成される)
  link.xml                … WebGL のコード削除で JSON 用の型が消えないようにする設定
Tools/
  run-tests.ps1           … テストをバッチ実行して結果を要約する
  serve-webgl.js          … WebGL ビルドをローカルで開くための簡易サーバー(Node.js)
Build/WebGL/              … WebGL ビルドの出力先(ビルドすると作られる)
```

### アセンブリの依存関係

```
DungeonGame.Core   (UnityEngine 参照なし / Newtonsoft.Json のみ)
   ↑            ↑
DungeonGame.Client   DungeonGame.Core.Tests
   ↑
DungeonGame.Editor
```

`DungeonGame.Core` は `noEngineReferences: true` なので、Unity の API を使うとコンパイルエラーになります。
将来はこのフォルダをそのまま ASP.NET Core のプロジェクトから参照し、サーバーで勝敗を再計算します。

## 遊び方

Unity エディタで `Assets/Scenes/SampleScene.unity` を開いて再生するか、WebGL ビルドをブラウザで開きます。
操作はボタンとマップのクリックだけです。

### 魔王モード

1. 層(1〜5層)を選びます。深い層ほど掘削予算が多く、土が豊か(土の器が大きい)なので、強いモンスターが生まれやすくなります。やり直したいときは層ボタンを押すと、その層を最初から掘り直せます。全部が土の状態から始まります。土の色は、緑っぽいほど養分が、青っぽいほど魔分が多いことを表します。
2. **掘る**:入口(水色)か掘った通路の隣の土をクリック(ドラッグも可)。掘削予算の範囲で掘れます。
   養分・魔分の多い土を掘るとモンスターが生まれます(層で解放された階級まで)。
3. **育てる**:「10秒/60秒/残り全部」で生態系を動かします。下位は土の養分を吸って増え、中位は下位を、上位は中位を食べます。
   死んだモンスターの養分・魔分は土に還ります。
4. **テスト防衛**:NPC 勇者(戦士・魔法使い・僧侶)を送り込んで様子を見ます。「10回(結果だけ)」で突破率もわかります。
5. **保存**:予算超過や、入口からゴールまでの道がない(完全封鎖)ダンジョンは保存できません。保存先はブラウザ内(PlayerPrefs)、
   エディタ/PC 版では `Application.persistentDataPath` にも JSON ファイルを書き出します。「JSON」ボタンで中身を表示・コピーできます。

### 勇者モード

1. 4職業(戦士・魔法使い・僧侶・盗賊)から3人を選びます(選んだ順が隊列順)。シードが同じなら同じダンジョンが選ばれます。
2. 勇者は自動で探索・戦闘します。プレイヤーは介入スキルを使えます(回数はラン全体で共有)。
   - **回復**:パーティ全員の HP を回復
   - **たいまつ**:ボタンを押してからマップをクリックすると、その周りの霧が晴れます(ゴールを先に照らすと迷わなくなります)
3. 層を突破すると報酬画面になります。スキル候補3つから1つを選び、スキルポイントを勇者ごと・能力値ごとに割り振ります。
   HP は次の層に引き継がれます。
4. 最下層(5層)の魔王を倒せばクリア。評価は★の数 = 突破した層の数(★5で魔王撃破)。層の数は layer_rules.json の層の数で決まります。
5. 結果画面で「ログを保存」すると入力ログ(JSON)が保存され、リプレイ画面で再生できます。

### リプレイ

保存済みの入力ログ(または貼り付けた JSON)からランを再生します。再生が終わると、記録された結果(★・最終状態)と
再計算の結果が一致するかを表示します。「検証だけする」で再生せずに一瞬で検証もできます。

## テストの実行方法

### Unity エディタから

`Window > General > Test Runner` を開き、`EditMode` タブで `Run All`。

### コマンドラインから(Unity CLI)

Unity エディタでこのプロジェクトを開いていない状態で、プロジェクトフォルダで実行します。

```powershell
unity test . --editor-version 6000.5.8f1 --mode EditMode --output Logs/test-results.xml
```

または結果の要約まで表示するスクリプト:

```powershell
.\Tools\run-tests.ps1
```

テストは 89 件(うち 4 件は開発用ツールで、通常は実行されない `Explicit` 指定)。主なテスト:

| 内容 | テストクラス |
|---|---|
| 決定論:同じ入力で再計算すると完全に同じ結果(乱数・生態系・攻略・ラン全体・ログからの再計算) | `DeterminismFoundationTests` `EcologyTests` `RaidTests` `RunTests` `ReplayTests` |
| 予算超過・経路封鎖のダンジョンは保存時に弾かれる | `DungeonGridTests` |
| スキル候補の抽選がシードで再現できる | `RunTests` |
| JSON のシリアライズ → デシリアライズで内容が変わらない(ダンジョン・入力ログ) | `DungeonGridTests` `EcologyTests` `ReplayTests` |
| 改ざんされた入力ログを検出できる | `ReplayTests` |

### 開発用ツール(Explicit テスト)

| テスト | 用途 |
|---|---|
| `NpcDungeonTools.NPCダンジョンを生成する` | NPC ダンジョンの JSON を作り直す |
| `NpcDungeonTools.自動プレイで星の分布を出力する` | 自動プレイヤーで 160 回ランを回し、★の分布を出す(バランス確認) |
| `EcologyDiagnostics.個体数の推移を出力する` | 生態系の個体数の推移 |
| `RaidTests.テスト防衛の結果一覧を出力する` | NPC 勇者の攻略結果の一覧 |

```powershell
unity test . --editor-version 6000.5.8f1 --mode EditMode --filter "DungeonGame.Core.Tests.NpcDungeonTools.NPCダンジョンを生成する" --output Logs/diag.xml
```

※ モンスターの HP などを変えたら NPC ダンジョンも作り直してください(スナップショットにモンスターの HP が入っているため)。

## WebGL ビルド

エディタのメニュー `DungeonGame > WebGLビルド`、またはコマンドラインから:

```powershell
unity build . --editor-version 6000.5.8f1 --target WebGL --execute-method DungeonGame.EditorTools.BuildScript.BuildWebGL
```

出力は `Build/WebGL`。gzip 圧縮+ブラウザ側での展開(decompression fallback)にしているので、どの Web サーバーでも動きます。
ローカルで確認するには:

```powershell
node Tools/serve-webgl.js
```

を実行して http://localhost:8080 を開きます。

## 設計メモ

### 決定論

- 浮動小数点は使わず、すべて整数(割合は % の整数)で計算します。
- 乱数は自作の xorshift128(`DeterministicRandom`)。`UnityEngine.Random` / `System.Random` は使いません。
  用途ごとにシードを派生させる(`RunState.DeriveSeed`)ので、用途を増やしても既存の抽選結果は変わりません。
- ロジックは固定ティック(1ティック=0.1秒)で進み、描画のフレームレートには影響されません(`FixedTickAccumulator`)。
- 処理順はすべて ID 順・固定の方向順。`Dictionary` の列挙順や `GetHashCode` には依存しません。
- 状態のハッシュ(FNV-1a)で「同じ結果になったか」を比べます。

### 入力ログと検証

勇者側の入力ログ(`RunLog`)には、シード・編成・各層の介入(ティック・種類・座標)・スキル選択・ポイント配分を記録します。
照合用に、抽選されたダンジョンの ID と中身のハッシュ、各層の結果、★、最終ハッシュも入れています。
`RunReplayer.Verify(log, data)` がログから再計算し、すべて一致すれば有効と判定します。
サーバーでは、クライアントが送ってきたログをこれで検証してから★を記録する想定です。

なお、検証が保証するのは「申告された結果が、ログの入力から本当に導けること」です。
たとえばたいまつを使う時刻を書き換えても結果が変わらないなら、それは「そう遊ぶこともできた正当なログ」として通ります。

### 音(BGM・効果音)

音の素材ファイルは使わず、`Assets/Scripts/Client/Audio` でファミコン風の音(矩形波・三角波・ノイズ)をプログラムで合成しています。すべてオリジナルです。

- **BGM**(`Music.cs`):タイトル/魔王の部屋/冒険(勇者の攻略中)/決戦(魔王の待つ層)の4曲と、突破・魔王撃破・全滅のジングル。曲は文字列の楽譜(8分音符ごとの音名とコード進行)で書いてあり、書き換えるだけで曲が変わります。
- **効果音**(`Sfx.cs`):ボタン、掘る、誕生、斬撃、魔法、矢、会心、被ダメージ、撃破、勇者が倒れる、回復、たいまつ、進化 など。
- 画面右下のボタンで「音:ON → BGM:OFF → 音:OFF」を切り替えられます(設定は保存されます)。
- WebGL 版では、ブラウザの決まりで最初に画面をクリックするまで音が鳴りません。

### モンスターの生まれ方

層による制限はなく、次の2つのパターンで生まれます(`monsters.json` で設定)。

| パターン | しくみ | 種族 |
|---|---|---|
| 土 | 掘った土の養分・魔分が誕生条件以上なら、その場所に生まれる。条件を満たす種族が複数あれば、階級が高く・条件の厳しいものが優先 | コケスライム、マナダニ、ヒカリダケ、ホラアナトカゲ、ショウセキゴーレム、アビスワーム、ヨロイムカデ |
| 巣 | 育成中、3×3以上の広い部屋の中に巣を作る(巣どうしは6マス以上離れる) | カゲコウモリ |
| 墓場 | モンスターが死ぬと通路に骨が残る。骨が6本以上積もった通路から、育成中に起き上がる | ドクロ魔導士 |
| 進化 | 生まれて一定時間たち、分裂できるほど育つと、分裂せずに別の種族に変わる | コケスライム→ヒカリダケ、アビスワーム→冥竜 |

特殊な誕生の体の分は、まわり(半径2マス)の土の養分・魔分から使います(養分・魔分の総量は変わりません)。
層ごとの「土の器」(`layer_rules.json` の `TileResourceCap`)が、1マスに溜まる養分・魔分の上限です。
浅い層は器が小さいので、強い種族の誕生条件に届かず、自然と弱いモンスターが中心になります。
モンスターが住みつくと、まわりの土の見た目がその種族らしく変わります(見た目だけで、保存データには影響しません)。

### 魔王側の検証

保存時に `DungeonValidator` が、予算超過・経路封鎖・外周の岩盤・入口/ゴールの数・層で解放されていない階級のモンスター・
ボスの設置などを検査します。予算は申告値ではなく、実際に掘られたマス数で判定します(サーバーでも同じ検証をする想定)。

### データの追加

- **層を増やす**:`layer_rules.json` に層を追加します(10層まで想定)。攻略する層の数は層ルールの数で自動的に決まります。新しい層の NPC ダンジョンは、`NpcDungeonTools` の設定に層を足して作り直します。
- **スキルを増やす**:`skills.json` に追加します。効果は `SkillEffectType` の組み合わせで書きます。
  新しい種類の効果が必要なら、`SkillEffectType` に追加して `SkillMath` / `RaidSimulation` に処理を書きます。
- **モンスターを増やす**:`monsters.json` に追加します(誕生条件・食性・捕食できる階級・戦闘能力)。
- **NPC ダンジョンを増やす**:`Resources/GameData/NpcDungeons` に JSON を置くだけで、抽選対象になります(読み込み時に検証されます)。

### 既知の制限・今後

- 攻略中は生態系が止まります(モンスターは勇者に向かってくるだけ)。
- 霧は壁越しにも見える簡易版です。
- 勇者側の UI で、魔王側で作ったダンジョンを攻略する機能はまだありません(オンライン化で「他の魔王のダンジョン」と置き換える想定)。
- バランスは仮です。自動プレイヤー(回復のみ使用、たいまつ不使用)120回で ★2 が約44%、★3 が約25%、★5(魔王撃破)が約6%。
- WebGL ではクリップボードへのコピーがブラウザの制限で動かないことがあります(JSON 欄から手動でコピーしてください)。
